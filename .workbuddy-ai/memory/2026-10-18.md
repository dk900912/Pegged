## 经验教训
- UseWindowsForms=true 会把 WPF 与 WinForms 的同名类型都拉进全局 using，~20 个名字要 alias
- 沙箱 git push 走不通时，blob→tree→commit→PATCH ref 是可靠 fallback
- 写多文件 XAML 项目时，模块级 dotnet build 失败要立即用 Edit 精修，不能批量 Write 触发循环保护
- 视觉验证要早做（Module 3 第一次截屏就知道渲染对了），后续模块可沿用同一套 Pegged.exe 冒烟

## 追加：UI 设计目标 100% 核对与修复（Phase 5）
用户要求"自己启动全流程端到端测试 + UI 设计目标与实际效果仔细核对"。执行后发现 5 个缺口，全部修复并重新发布：
1. **双击预览打不开**：`PreviewMouseLeftButtonDown` 中 `CaptureMouse()` 破坏 WPF `MouseDoubleClick` 检测 → 改用手动跟踪 `_lastClick` 时间戳（400ms 内二次点击触发预览）
2. **卡片悬停镀铬不完整**：规范要求底部 Copy/Crop/Delete 操作行 + 衣夹张开动画 → 添加 `ActionRow`（半透明暗底 + 3 个 28px 圆按钮）+ `_pegHover` Spring 驱动 `ScaleTransform`
3. **裁剪窗口非全屏遮罩**：规范要求冻结桌面 + 九宫格白线 + 底部浮动操作栏 → 重写为 `WindowState="Maximized"` + `Background="#E6000000"` + 4px 33% 白线网格 + 玻璃 FAB
4. **设置窗口尺寸/导航偏差**：规范要求 720×560 / 左栏 240px / 图标+副标题导航 / 28px 页头 → 全部对齐
5. **空状态绳子无微风 + 边缘胶囊无流光**：规范要求 ±1.6°~3.4°  breeze + 水平流光 → `LineWindow` 加 `_breezePhase` 贝塞尔控制点摆动；`EdgePillWindow` 加本地 `LinearGradientBrush` + `GradientStop.Offset` 滑动
