**实际发现并修复（均有实证）**
1. 双击启动后挂绳窗停在 (96,96)、感应条 (32,32)：`PlaceOn()` 在 `Show()` 前调用，`MoveTo()` 句柄为0时静默 return。修：显式 `SetProcessDpiAwarenessContext(PerMonitorV2)` + `OnSourceInitialized` 补定位 + 用目标屏 scale。
2. 默认设置下挂绳**永不展开**：`IsFullScreen()` 枚举所有窗口，Windows 常驻 Program Manager 与 IME 宿主满屏 → 永远判"有全屏应用"。修：只看前台窗口 + 跳过 cloaked/TOOLWINDOW/NOACTIVATE + 比 Physical 矩形。
3. 重复启动出现第二套窗口 → 命名 Mutex 单实例。
4. 裁剪窗 8 手柄不可拖（父 Canvas `IsHitTestVisible=False`）+ `Children[i+1]` 越界崩溃 → 重写 CropWindow。
5. 拖拽 Esc 把卡片当 Move 删除 → None 不再回退成 initial。
6. 全局热键随设置窗关闭失效 + 失败 hook 泄漏 → 收归 App 常驻，Register 返回 bool。
7. 空绳微风不播（`OnFrame` 的 `AtRest` 早退）；感应条 4s→2.4s、0.55-0.90→0.35-0.75；首启 4s→5s。

## 第四轮：crash.log 抓到的两个静默闪退（已修）

- `CaptureStore.OnChanged()`：`Drop`/`LetGoLocked` 的 `ContinueWith(..., TaskScheduler.Current)`
  在非 UI 线程发起时会落到线程池 → `Changed` 从后台线程触发 → `LineWindow.UpdateHint()`
  跨线程访问 `CardLayer.Children`。改为 `OnChanged` 里统一 `Dispatcher.BeginInvoke`。
- `LineController.Peek()`：`ScreenshotWatcher` 在 watcher 线程上调用，`Peek → Reveal →
  PlaceOn` 会 `SetValue(Width/Height)`。**每张新截图都会触发**。改为入口 `CheckAccess()`。
- 压测（挂 3 张 → 单张下架 → 全部清空 → 外部删文件剪枝）后 crash.log 为空。
- 教训：覆盖层应用没有控制台，未处理异常必须落盘，否则只能看到"窗口突然没了"。

## 第六轮：用户报障「挂 2 张以上时第一张很难点选到复制」（已修复）

- 按 `diagnosing-bugs` 流程走：先建红得动的复现循环（`scripts/e2e/repro_first_card_click.py`，
  逐点真点 + 剪贴板断言），再定位、再修、再回归。
- 根因（实测，不是推断）：`UpdateHint()` 只把空态提示的 `Hint.Opacity` 置 0，
  **WPF 中 Opacity=0 的元素依然参与命中测试**，把本该落到图片上的点击整块截走。
  提示是居中布局，正好压在第一张卡的右半部分。UIA `ElementFromPoint` 逐点归属图拍到：
  卡片中部那些点的所有者是 `Text:HintText/HintSub`，不是 `ThumbImage`。
- 修复：`Hint` 改用 `Visibility` 显隐（只有 `Hidden` 才退出命中测试）+ `IsHitTestVisible=False`；
  顺带给同源的 `NameBar`、`ActionRowBg` 也加上 `IsHitTestVisible=False`（按钮本身仍可点）。
- 关键坑：探针自己会在 3×3 网格里点到悬停栏的删除钮，把卡片点掉、布局漂移，
  误判成"第一张点不动"——探针必须避开按钮矩形（记下 12 个 hover 控件 rect 再跳过）。
