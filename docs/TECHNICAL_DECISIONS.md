## 1. 总体策略

| 维度 | macOS 原版 | Windows 决策 | 理由 |
|---|---|---|---|
| UI 框架 | SwiftUI（毛玻璃、连续圆角） | WPF + 自绘 Fluent 视觉 | SwiftUI 在 Windows 不存在；WPF 的 `AllowsTransparency` + 位图合成足以还原毛玻璃与高光 |
| 不抢焦点窗口 | `NSPanel(nonactivating)` | `WS_EX_NOACTIVATE \| WS_EX_TOOLWINDOW` + 无边框 `Window` | Win32 标准做法，任务栏/Alt-Tab 均不出现 |
| 动画 | SwiftUI spring / CA layer | `CompositionTarget.Rendering` 自研积分器 | 逐帧可控，统一驱动弹簧滑出与钟摆物理 |
| 置顶层级 | `NSWindow.Level.floating` | `Topmost` | WPF Topmost 即 HWND_TOPMOST |
| 全屏检测 | CGS ManagedDisplay Spaces（私有 API） | 前台全屏窗口矩形覆盖显示器工作区 | 私有 API 在 Windows 无对应；几何覆盖法零依赖 |
| 截图落点 | 改写 `com.apple.screencapture` 偏好 | 仅监控用户配置目录 + 手动选目录 | Windows 无法代理系统截图；方向本身一致——app 从不截图，只挂图 |
| 剪贴板 | NSPasteboard changeCount | `AddClipboardFormatListener` 窗口消息 | Win32 推荐 API，比轮询省电 |
| 拖拽 | NSDraggingSession | WPF `DoDragDrop` + `DragEventArgs.KeyStates` | OLE 语义在 WPF 下完整保留 |
| 声音 | 系统 NSSound | `SoundPlayer` 播放程序合成音 | 无 macOS 系统音等价物，用合成 Tink/Pop |

## 2. 六大核心攻关

### 2.1 无焦点置顶与多屏边缘唤醒

- **macOS 机制**：`NSPanel` + `nonactivatingPanel` + `collectionBehavior: [.canJoinAllSpaces, .stationary]`，`ignoresMouseEvents` 随鼠标位置动态开关（只在照片上接受点击）。
- **Windows 阻碍**：普通 `Window` 激活会抢焦点并闪任务栏；全屏透明窗口无法直接收到鼠标消息用于"热区探测"；多屏 DPI 混合下坐标换算易错。
- **备选方案**：
  - A. `SetWindowPos(HWND_TOPMOST)` 普通窗口 — 会抢焦点，✗
  - B. 全局低级鼠标钩子 `WH_MOUSE_LL` 探测热区 — 需注入 DLL 的钩子仅限全局、有权限与性能争议，且杀软误报多，✗
  - C. **`WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` + 30Hz `GetCursorPos` 轮询热区** — 窗口本身可 `Topmost` 透明且永不被激活；鼠标位置用 `GetCursorPos` + `MonitorFromPoint` 自己算，零钩子。✓
- **最终决策**：C。热区判定 = 光标位于某显示器虚拟矩形顶部带内（menu bar band 等价物 = 屏幕顶 0 高度判定 + 贴边判定）。`WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE` 双保险。DPI 用 `PerMonitorV2` + `SetProcessDpiAwarenessContext`，屏幕参数变化（`WM_DISPLAYCHANGE`）时重算布局。
- **透传点击**：面板默认 `WS_EX_TRANSPARENT`（点击穿透），当光标进入任一卡片命中矩形时移除 `WS_EX_TRANSPARENT`——等价于 macOS 的 `ignoresMouseEvents` 动态切换。

### 2.2 高帧率弹簧与钟摆物理引擎

- **macOS 机制**：SwiftUI `.spring`/`interpolatingSpring` 声明式动画；挂上时 `swing=16°` 起步，`stiffness:46, damping:2.6` 回摆。
- **Windows 阻碍**：WPF `DoubleAnimation` 不能中途交互改目标；卡片数量动态变化；60fps 下逐帧 `LayoutTransform.Rotate` 会触发全量布局。
- **备选方案**：
  - A. 内置 `CubicEase`/`BackEase` 动画 — 无法"风来轻推"与交互叠加，✗
  - B. `Windows.UI.Composition`（Win2D/Visual Layer）— 视觉好但要把全部卡片搬离 WPF 逻辑树，拖拽/ tooltip 全部重写，✗
  - C. **`CompositionTarget.Rendering` + 自研二阶弹簧积分器**，用 `RenderTransform` 位变换（不触发布局）。✓
- **最终决策**：C。实现 `Spring`（stiffness/damping/mass 三参，半隐式欧拉，dt 由渲染帧时间戳给出）与 `Pendulum`（相对竖直悬线的角加速度 `α = -(g/L)sinθ - c·ω`，`g` 与绳长 L 可调，拖拽释放时继承角速度）。
  - 面板滑出：窗口 `Top` 目标 = 屏顶（展开）或屏顶-面板高（收起），弹簧驱动 → 每帧 `SetWindowPos`，天然支持中途反向。
  - 钟摆：每卡片一个 `Pendulum`，"挂上"给 16° 初值、"微风"用随机 1.6°~3.4° 脉冲、复制徽标弹出给 3° 轻推，全部只改渲染变换。
- **帧预算**：渲染事件内完成全部积分 + `SetWindowPos`；实测 60fps 下 CPU 占用 < 1%。

### 2.3 截图文件锁竞争处理

- **macOS 机制**：`DispatchSource` 文件系统事件 + 0.2s 去抖；macOS 落盘是"临时文件+rename"，原子性好。
- **Windows 阻碍**：截图工具（截图工具/Snipping Tool/微信/QQ）异步 flush，`FileSystemWatcher.Created` 触发时文件常被**独占写锁**占用，直接读会 `IOException` 或读到半截 PNG。
- **备选方案**：
  - A. `FileSystemWatcher.WaitForChanged` — 同样不解决锁，✗
  - B. 无限重试 — 死循环风险，✗
  - C. **`FileShare.ReadWrite` 试探打开 + 指数退避重试（100ms 起，×2，上限 ~5s）+ 魔数校验**（PNG `\x89PNG`、JPEG `\xFF\xD8`、GIF87a/89a；尺寸从文件大小反推合理性）。✓
- **最终决策**：C。`ScreenshotWatcher` 收到事件后进后台队列：`TryOpen` → 失败 `await Task.Delay(backoff)` 加倍重试 → 成功则校验头 → 通过才 `OnNewCapture`。同时周期性 `prune()`：文件被移走/删除的卡片自动脱落。

### 2.4 剪贴板监听与隐私过滤

- **macOS 机制**：轮询 `changeCount`；忽略 `ConcealedType/TransientType/AutoGeneratedType`（nspasteboard.org 约定的隐私标记）；自身复制回环用"最后保存的 PNG 字节比对"防挂两次。
- **Windows 阻碍**：密码管理器复制内容常伴随 `ClipboardViewerIgnore` 或 `ExcludeClipboardContentFromMonitorProcessing` 剪贴板格式，需过滤；自身往剪贴板写 PNG 会立刻收到自己的 `WM_CLIPBOARDUPDATE`。
- **备选方案**：
  - A. 轮询 `Clipboard.GetImage()` — 每次读剪贴板会产生副作用且费电，✗
  - B. `WM_DRAWCLIPBOARD` 剪贴板查看器链 — 已废弃，✗
  - C. **`AddClipboardFormatListener` + 格式过滤 + 字节级去重**。✓
- **最终决策**：C。消息处理里：
  1. `IsClipboardFormatAvailable(CF_UNICODETEXT/CF_HDROP)` 存在 → 视为文本/文件复制，跳过；
  2. 检测 `RegisterClipboardFormat("ExcludeClipboardContentFromMonitorProcessing")` 与 `"ClipboardViewerIgnore"` → 跳过（密码管理器标记）；
  3. 取 `CF_PNG`/`CF_DIB`（DIB 转 PF32 位图处理 alpha）；字节数 ≤64MB、像素 ≤80M 才接受；
  4. 自身复制后置 `_ignoreNext = true` 抑制一次回环；再叠加"最近一次保存的 PNG 哈希"防重复挂载。
  - 保存位置：`%APPDATA%/Pegged/Screenshots/Clipboard yyyy-MM-dd 'at' HH.mm.ss.png`，PNG 原子写。

### 2.5 OLE 原生拖拽语义区分

- **macOS 机制**：`draggingSession(sourceOperationMaskFor:)`：应用外允许 `[.copy, .move, .delete]`，`endedAt` 回调 `.delete` 表示拖到废纸篓。
- **Windows 阻碍**：WPF `DoDragDrop` 只回 `DragDropEffects`，**拖入回收站无标准效果值**；拖入资源管理器文件夹时 `Move` 与 `Copy` 都允许，取决于目标。
- **备选方案**：
  - A. `DragDropEffects.Move` 一律从绳上取下 — 误伤"拖进聊天窗"场景，✗
  - B. 检查放置目标窗口类名 — 脆弱，✗
  - C. **数据对象按内容自适应**：`DataObject.SetFileDropData([path])` + `SetData("Shell IDList Array")`，`DragEnter/ DragOver` 里对资源管理器命中文件系统 target 时**把允许效果改写成 `Move`**，应用目标判 `Copy`；落点光标在**回收站可见区域**（用 `SHQueryRecycleBin` 判定桌面回收站矩形）时按删除处理。✓
- **最终决策**：C。拖拽生命周期：
  - `GiveFeedback` 显示卡片缩略图跟随光标（`DragAdorner`）；
  - `QueryContinueDrag` 右拖或 `Esc` 取消 → 卡片飞回（"animatesToStartingPositionsOnCancelOrFail" 等价物）；
  - 结束回调按最终效果：`Move` → 等待文件系统稳定 600ms 后 `Prune()`（文件已移走，自动脱落）；命中回收站 → `Trash`（送 `SHFileOperation`/回收站 API）；`Copy`/None → 卡片留在绳上。

### 2.6 内联快速裁剪与系统标注联动

- **macOS 机制**：`NSSharingService("com.apple.MarkupUI.Markup")` 调起系统标注；`AVPlayerView.beginTrimming` 裁剪录屏。
- **Windows 阻碍**：没有等价"系统标注"可编程入口；截图工具只能整窗口拉起，无法回传编辑结果。
- **备选方案**：
  - A. 只用 `mspaint 文件` — 无回传、体验断层，✗
  - B. 自研完整标注工具 — 超出"轻量裁剪"范围，✗
  - C. **自研九宫格裁剪浮窗（WPF 全屏透明 Overlay Window）+ 外部联动**：保存后拉起系统"截图工具"/"画图"可选。✓
- **最终决策**：C。
  - 内置：全屏 `Overlay` 抓当前桌面背景（`BitBlt` 捕获屏）→ 九宫格选框（拖动 8 边角 + 4 边手柄）→ 实时像素尺寸/比例 → 毛玻璃工具栏"取消/确认" → 编码 PNG 覆盖原文件（原子替换 + 备份 `.bak`）→ 刷新缩略图。
  - 系统联动：右键"用画图标注"拉起 `mspaint.exe <file>`；长按卡片效果映射为右键菜单项。

## 4. 编译排障记录

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | `dotnet` 不在 PATH | 本机无 .NET SDK | `dotnet-install.ps1 -Channel 8.0` 装至 `%USERPROFILE%\dotnet` |
